# 状态与审核呈现

## 1. 六种状态

每个模块任何时刻只处于一种状态。输出开头和飞书推送都带状态标记。

| 状态 | 标记 | 含义 | 对应 AgentTeams / 飞书 |
|---|---|---|---|
| 空闲 | `[空闲]` | 没有任务 | 成员 idle |
| 思考中 | `[思考中]` | 在理解任务、读投喂和记忆 | running；飞书 Round 卡 🤔 |
| 工作中 | `[工作中]` | 在产出交付物 | running；飞书 Round 卡 🔧 |
| 等待 | `[等待审核]` / `[等待确认]` | 等老板审核或回答问题 | 审核卡 / 问询卡已发出 |
| 阻塞 | `[阻塞]` | 依赖未完成、打回 2 次后第 3 次、API 不可达、超预算 | 任务挂起；必须写明卡在哪、需要谁做什么 |
| 完成 | `[完成]` | 已交付并写回记忆 | 任务完成；backgroundPush 推送 |

## 2. 三级可见

| 级别 | 看什么 | 在哪看 | 什么时候用 |
|---|---|---|---|
| 1 状态 | 每个模块一行：状态 + 当前一句话 | 飞书推送 / Round 卡 | 默认。不打扰，扫一眼就知道 |
| 2 预览 | 任务依赖图、成员名单、进度 | DSH Web UI 的 AgentTeams 活动面板 | 想知道「卡在哪、谁在干」 |
| 3 接管 | 模块的完整对话 | 活动面板点成员图标进入对话，直接发消息 | 需要亲自纠偏 |

详细执行步骤默认不推送，只在第 2、3 级查看。

## 3. 审核卡片

### 3.1 交付审核卡（默认唯一阻塞点）
```
[等待审核] 任务 P001 · 视频创作 · 成品前
交付物：projects/P001/（脚本 + 分镜 + 时间线包）
依据投喂：思维 T-base-02、T-base-04；风格 S-01-5
自检：通过 6/6 · 反调官：3 个风险（见附件）
预计消耗：xx k token

[通过]  [打回]  [改方向]
改方向 / 打回原因（一句话）：____________
```
- 实现：飞书插件的交互问询卡（选项 + 文字输入）；Web UI 中为同样的问询卡。
- 「改方向」：captain 定位受影响模块，回复「重做 X，保留 Y，理由」，不要求老板指定文件。
- 「打回」同一模块 2 次后，第 3 次转 `[阻塞]`，由老板决定。
- 不回复：24 小时提醒一次（triggers.md R1），**永不自动通过**。

### 3.2 红线确认卡
删除原始素材或投喂、改 API Key / Webhook、公开发布、付款或授权：
```
[等待确认] 红线操作：【操作】
影响：【会改变什么，能否撤回】
[允许一次]  [拒绝]
```
- 实现：飞书插件的权限审批卡（会话审批策略须为 ask；超时即拒绝）。

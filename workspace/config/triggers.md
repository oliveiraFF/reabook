# 触发机制

让工作台在老板不发话时也能干活。所有触发都只把任务带到**审核节点**，不越过审核、不发布。

> 前提（PRD v1.7）：定时任务只在 DSH 运行时触发。当前在本机运行，电脑关机或 DSH 未启动期间的触发会错过；
> Mac mini 常驻部署（第 10.1 节）之后另议。错过的触发不补跑，由 C2 每日状态汇总报告「错过了哪些触发」。
> 本表所有定时任务（C1–C4、H1）都依赖 `@aiwayds/dsh-cron`，尚未安装；创建任何一条都属于红线，须老板确认。

## 1. 定时触发（第一版）

插件：`@aiwayds/dsh-cron`（标准 cron 表达式；任务绑定到一个会话）。
创建方式以插件 README 为准。DSH 自带的 `dsh-schedule` 只用于一次性提醒。

| ID | 时间 | cron | 唤醒模块 | 做什么 | 停在哪 |
|---|---|---|---|---|---|
| C1 | 每周一 09:00 | `0 9 * * 1` | idea | 读思维、类型投喂，出 5 个选题 | 审核卡：通过 / 打回 / 改方向 |
| C2 | 每天 21:00 | `0 21 * * *` | captain | 汇总当天各模块状态与错过的触发，推飞书 | 只推送，不阻塞 |
| C3 | 每周日 20:00 | `0 20 * * 0` | captain | 清理各模块 memory.md（超 50 条合并）、清 TODO 挂起任务 | 推送清理摘要 |
| C4 | 每周五 18:00 | `0 18 * * 5` | captain | 写周报 `reviews/周报/<年>-W<周>.md`：各模块完成、打回、OKR 进展、token、下周计划（PRD FR-16） | 只推摘要，不阻塞 |
| H1 | 每天 09:00–23:00 每小时 | `0 9-23 * * *` | captain | 心跳：查看各成员状态，找出超过 60 分钟无进展、报错或阻塞的成员 | 有问题才推 `[阻塞]`（卡在哪、谁该处理）；不自动重启或改派 |
| R1 | 审核卡发出 24 小时未回复 | dsh-schedule 一次性提醒 | captain | 再推一次审核提醒 | 不自动放行 |

## 2. 事件触发

| ID | 事件 | 第一版 | 唤醒模块 | 做什么 |
|---|---|---|---|---|
| E1 | 老板飞书私聊发消息 | ✅ 飞书插件 | captain | 判阶段 → 路由 |
| E2 | 上游模块完成（AgentTeams 任务依赖） | ✅ | 下游模块 | 例：script 完成 → 唤醒 edit；asset 可并行 |
| E3 | 老板说「素材到了」 | ✅ 手动 | asset | 扫描 assets/ 新文件，建索引 |
| E4 | 素材放进文件夹自动建索引 | ⏸ 无现成插件 | asset | 后续再接 |
| E5 | 外部 Webhook（平台数据、表单等） | ⏸ 官方 `@deepseek-ai/dsh-webhook` latest 仍为 alpha | data | Phase 2 |

## 3. 规则
- 每次触发在对应模块 `history.md` 记一行，「触发方式」写 C1 / E2 等编号。
- 定时任务连续 2 次被打回 → 自动暂停该定时任务，推飞书说明，等老板决定。
- 新增定时任务属于持久配置，必须老板确认后才创建。
